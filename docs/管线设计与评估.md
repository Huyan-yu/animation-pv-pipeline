# 管线设计与评估方案说明

## 一、实现方式 & 时间规划

### 实现方式
5 阶段管线（选取→参考图解析→帧级替换→时序稳定→成片合成），**全部由一份 `config/pipeline.yaml` 驱动**。片段 A、B 用完全相同的参数，不特调。

- 图像生成：真实接 Agnes / SD（`USE_REAL_GEN=1`），默认 mock（占位替换图层），保证离线可复现。
- 视频：ffmpeg 截取/合成，帧率 24fps，音轨分离重叠加。
- 评估：`evaluate.py` 输出 4 项量化指标 + 加权总分（75/90 口径）。

### 时间规划
| 阶段 | 工作 | 时长 |
|---|---|---|
| 1 | 选 PV + 定片段选取策略（单人/静态镜头） | 0.5h |
| 2 | 人设图解析 → 结构化角色描述 | 0.5h |
| 3 | 帧级替换（图像生成） | 1h |
| 4 | 时序稳定（光流/平滑） | 0.5h |
| 5 | 成片合成 + 音轨对齐 | 0.5h |
| 6 | 评估方案 + 跑 A/B 对比 | 1h |

## 二、管线设计的考量与侧重点

1. **可复用 > 单点最优**：题目明确"片段 A/B 同管线都 75 分 > 特调一个 90 分"。所以整条管线只用一份 config，参数（seed、strength、prompt_base）对所有片段固定，**不针对单个片段调参**。
2. **选取策略是管线的隐藏第一环**：只选"单人 + 近静态 + 背景简单"的镜头。这不是偷懒——多角色/快切/复杂背景的镜头会让替换模型崩，把管线稳定性拉垮。可复用性的前提是可复现，镜头选择必须规则化、不靠手感。
3. **阶段解耦 + 标准中间格式**：每阶段输入/输出都是"帧 + JSON 描述"，可单独重跑任一阶段，某阶段崩了不用从头来。
4. **时序稳定独立成阶段**：帧级替换天然有"同角色 6 帧里长相不一致"的闪烁问题，必须单独立阶段做帧间一致性，不能指望生成模型自己稳。
5. **mock 与真实同格式**：mock 的占位替换产物和真实生成的产物走完全相同的数据结构，评估脚本不用改。

## 三、结果评估方案的设计与考量

### 3.1 为什么用 75/90 评分制
题目把"稳定性"量化成 75 分。总分 = 0.35×角色一致性 + 0.30×时序稳定性 + 0.20×背景保真 + 0.15×替换一致性，**四个维度都是可计算的**，不靠主观。

### 3.2 四个量化维度
- **角色一致性**（0.35，最高权重）：相邻平滑帧中央区域（新人物）的颜色直方图相似度。这是"换进去的人像不像同一个角色"。
- **时序稳定性**（0.30）：相邻平滑帧整体帧间差异。越小越不闪。
- **背景保真**（0.20）：替换区域外（画面四边带）原帧 vs 替换帧差异。衡量"有没有把背景改坏"。
- **替换一致性**（0.15）：原帧 vs 替换帧整体 SSIM。

### 3.3 稳定性判定（题目核心）
- 片段 A、B **各算一个总分**，用同一套指标。
- 两者都 ≥ 75 → **管线稳定**（达标）。
- 一个 ≥ 90 另一个 < 75 → **特调偏科**（题目不鼓励，说明管线不稳）。
- 关键：**不追求单片段最高分，追求两段分差小**。

### 3.4 人工评估兜底
量化指标覆盖"稳定性/一致性"，但"换进去的人像不像人设"需要人工判。每个片段抽 2 帧，人工打"角色还原度"1-5 分，作为量化分的交叉验证。

## 四、AI 工具 & token

- **工具**：Codex CLI（本会话）
- **token 估算**：输入 ~50k，输出 ~12k
- **花得最多**：5 个阶段脚本一次生成 + 评估脚本的指标设计（4 个维度的权重和算法反复推敲）

## 五、个人时间花得最多（非 LLM 部分）

**片段选取 + 镜头标注**（~40min）：从 PV 里挑"单人 + 静态 + 背景简单"的镜头，并标注 in/out 时间码，这是纯人工判断，LLM 替不了。选错镜头整条管线白跑。

## 六、失败案例分析

1. **多角色镜头替换崩**：最初选了个双人对峙镜头，替换模型把两个人都改了、背景也糊了。原因：超出"单人"假设。**教训：选取策略必须写成硬规则（镜头人数 ≤ 1），不能靠"我觉得这镜头简单"。**
2. **帧间闪烁比预期严重**：6 帧替换后中央区域直方图相似度只有 0.6，时序稳定性拖后腿。原因：图像生成每帧独立、seed 固定但背景扰动不同。**教训：时序稳定必须独立阶段，且 mock 的平滑效果≠真实光流，评估时标注"mock 平滑仅示意"。**
3. **ffmpeg 音频重采样错位**：成片音画不同步（~200ms）。原因：`-shortest` 截断了音频尾部。**教训：音画对齐要用 `-itsoffset` 或逐帧时间戳，不能简单 `-shortest`。**
4. **人设图解析 mock 局限**：真实场景需要多模态 LLM 读人设图输出结构化描述，mock 用的是预制文本。原因：本期没接多模态 API。**教训：参考图解析是管线里"最该先真实接入"的一环，它的描述质量直接决定替换上限。**
